# Every .rs file opens with a header and Parts in one order

## Context
The 2026-10-15 structure round found the longest files unreadable from the top: nothing said what a file held or where its logic ended. The shape follows the system-test files of a reference console. The tool was first `lumacore-banner`; 25.11 renamed it, since the startup art is the splash and "banner" stayed an open command word.

## Decision
Every `.rs` file opens with its ANSI Shadow file banner and the tag line `// FILE: <name>`, then a `//!` module doc in a fixed shape: one sentence of purpose, `Owns:`, `Doesn't own:` (saying where that lives), `Entry points:`, `Decisions:`. A crate root may instead carry one `//!` line pointing at its README (see crate-readme). The file's categories are Parts, each a banner plus `// PART: <NAME>`, from a fixed vocabulary in a fixed order: TYPES · INIT · REGISTRY · COMMANDS · LOGIC · VIEWS · IO · HELPERS · TESTS; a file uses the Parts it needs and never invents one. Inside a Part, Sections are a star box at the width tidy checks (they replace the old `// ── X ──` lines); inside a long function, Steps are `// ----- Name -----`. Banners are generated by `./scripts/unix/headers` (the crate `lumacore-headers`), never drawn by hand; all of these are plain `//` comments so rustdoc stays clean.

## Consequences
A new or moved file gets its banner, labels and Parts before it is committed; an old file gets them when its area is touched. `banners_match_their_tag` re-renders every tag line and fails if the art differs; `headers_stand_in_order` checks the labels, the Part order and what may stand before the first Part; `files_have_headers` is the ratchet of headerless files, which only goes down. Open: the last headerless files, crate by crate.
