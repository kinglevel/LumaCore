# The slab is the kit's one action block

## Context
A fixed function block, ours. The user asked for it beyond the setup menus — "we also need the slab in some other menus now, like the user and userprofile menu add and delete, make sure to unify this in the UI as a tidy requirement" — and for "minimal icons and standard colors".

## Decision
Every window or menu that lists objects puts its actions in `<luma-slab>` (`kit/slab.js`), acting on the selection of its `<luma-grid>`. Left, in fixed order: Select · New · Copy · Cut · Paste · Delete · Oops · Import · Export (+ Edit); right: the tab's actions, a few bound cells and `<luma-power>`. Each standard action has one icon in a standard colour token `--lc-act-*` (Delete turns alert only when it applies); the icon carries the colour, labels stay plain and carry the count ("Delete 3"). Actions that don't apply are greyed with the reason; deleting several asks once; hardware rows grey New / Cut / Delete / Import. An action may declare `Action.short` for a narrow cell; on a phone the slab is one bar with ⋯ More (see phone-desk-miniature). Cut / Copy / Paste work the per-user clipboard (see clipboard-of-live-guids).

## Consequences
No hand-made New / Copy / Cut / Paste / Delete / Import / Export buttons or action rows outside `slab.js` — tidy `frontend_actions_only_in_the_slab` (`tidy: slab-ok (<reason>)` only for a window's own settings header). Slab cells come from the verbs the object really has; a planned verb shows "… is planned". A new action is a `MenuDef` `Action` with a command-line template (see menudef-luma-setup).
