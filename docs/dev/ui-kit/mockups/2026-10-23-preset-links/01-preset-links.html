Preset links: Update, Recast and Extract

When you call a preset, the programmer keeps the preset's GUID with each value. A cue stored from that programmer holds the link and no copy of the value. Playback reads the preset when it compiles the plan, so changing the preset changes every cue that uses it. Update puts your changes back where they came from, Recast brings new or removed attributes into the cues, and Extract turns links into plain values.

Decided so far: cues store the link only; deleting a preset that cues use asks, then writes the values into those cues; the Device Sheet gets a Show setting; Update is one ask with a preview; Update offers Recast, and there is a Recast word too; Extract comes now, embedded presets later; the words Update (for presets), Recast and Extract join lum.md.

The Update ask

One server-held dialog, so every client and the terminal show the same thing. It is a reference tree: each preset your values came from, with the presets it holds nested under it and an S / G / U badge for its data level (selective, global, universal). Each row has its own Update button. Open a row to see what changes, choose which fixtures, see the cues that follow and freeze any cue that should keep the old look, or make the update a new preset. The preview shows the lines that will run, and the whole update is one Oops step. Try it.

How it is built

  • The link. Value.preset (the preset's GUID) already rides from At Preset into the programmer and Store Cue. With "link only", a cue value becomes the link and the attribute, with no steps of its own.
  • Playback. The plan compiler looks each link up in the preset (the fixture's own entry, else the universal one). A preset change marks the sequences that use it, so their cached offers are rebuilt. Nothing runs in the background and nothing is ever stale.
  • Back-references. A preset → cue parts index, rebuilt on load and kept by the change path. It gives "3 cues use it", the previews, Recast and the delete ask, and the pool's use count gets cues as well as programmers.
  • The ask. Update alone opens it, listing every preset and cue the programmer's values came from. Each choice is a line: Update Preset 3 /Merge · /Add · /Overwrite, Update Sequence 1 Cue 2 /Original, Recast Preset 3. Rights: Presets for presets, Program for cues.
  • Store Preset keeps writing plain values. A value already linked to another preset is flattened, until embedded presets come with a cycle check.
  • Tests on the rig. The demo show gets one sequence whose cues use Presets 1–3: Store, call, Update, Recast, Extract, delete then Oops, and the Device Sheet's Show.
