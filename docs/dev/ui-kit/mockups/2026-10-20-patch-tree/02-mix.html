What the drawing assumes (each a small rule; say where it is wrong)

OrderTree order — the file's order, each node's children by their order (§40 6) — is the grid's default. A column sort (Sort · Number, Name, Address) sorts within each node; the nodes keep their places. The old flat list is the same grid with every node folded away: a "Flat" switch beside Sort.
A node rowNo number: the No cell shows its second id (Media 7003); type Grouping; Address —; a Count column (deep count). The row folds with its arrow; a tap on the row selects the node (one row, §40 11), Thru and the lasso take the rows in between as drawn — fixtures and nodes alike.
Fold stateKept on the device per grid (like the window's scroll row, never in the show). Opening the dialog: the picked node open one level, the rest folded. Unfold all / Fold all in the grid's ⋮ header menu.
The sidebar pickScopes the grid to the subtree, the picked node its first row (so its own cells can be edited there). Direct | Deep as the Tag grouping has it; Deep is the default for this tree.
CountsThe sidebar and the Count column count fixtures only (the 23 folders are not fixtures): "1 348 fixtures · 23 folders". ls and the tree chip follow.
The layer's own fixturesAfter its folders, as the file has them. The 37 on the layer and PIXSTICK's 8 are the "No folder" fixtures of the old sidebar; there is no such node any more — "No MVR node" stays for a fixture outside every layer (a fixture stored by hand today lands there; the Insert page decides where it should land).
PhoneThe tree sheet lists the nodes as the sidebar does; the list folds the same way, the arrow a 44 px target.

Question 2 · is this the mix?

A · Recommended

As drawn

Sidebar = nodes only; grid = the tree in file order with folding node rows; a column sort orders within a node; Flat folds everything away.

B

As drawn, but a column sort flattens

Sorting by Number, Name or Address drops the node rows to the end (today's "0" rows) and lists the fixtures flat; tree order comes back with Sort · none.

Against: two shapes of the same list; the folders jump around on a sort.

C

Nodes as headers, no folding

Node rows are separators the fixtures sit under, never folded; the sidebar is the only way to narrow the list.

Against: 1 371 rows always; a stage can't be closed.
