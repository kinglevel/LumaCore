Tags

A tag is a node in one tree, Root.ShowData.Tags, with one parent and numbers per parent (Tag 1.1.1 = All › Lx1 › Right). Every show object can carry tags as GUID links. A tag reaches its own objects plus everything under its children, and a verb on a tag runs on each object that takes it. Pick a state below. The command lines are sketches for the lum.md discussion.

The tree
  • One parent per tag, numbered within the parent; a move renumbers. Links are GUIDs, so tagged objects never notice.
  • Names are unique among siblings. Tag "Right" works while only one Right exists; owner first narrows it: Tag "Lx1" Tag "Right".
  • Assign Tag 1.1 At Fixture 5 gives fixture 5 only Lx1. It then counts as part of All (through the tree), but not of Right.
Verbs on a tag
  • Tag 1.1 alone: its default verb, which selects its fixtures, deep.
  • Off Tag "All": Off on everything under All that takes Off (fixtures are knocked out, sequences turned off), with a summary of what was skipped.
  • Tap in the pool window: a tag with children folds open. Otherwise the tap runs the tag's own Action, or the window's default action. Today that is only Select; Go+, Off and Toggle are planned for playback.
Live and the Devices claim
  • Tags is a live column. Tagging fixtures works while Bob holds Devices: the change goes live and into his draft, unless he changed that fixture's Tags in the draft.
  • Tagging sequences, groups and other objects needs no claim.
  • Deleting a tag never deletes objects, only their links to it.
