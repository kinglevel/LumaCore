Patch setup dialog

All the decisions so far, in the kit's setup dialog. The dialog is Devices › DMX › Patch: the claim and the draft cover all of Devices, DMX is the first device kind, and Metadata holds the MVR layers and classes. The left side is the Luma layer tree, with a ≡ menu on the selected layer. One <luma-grid> serves the Live Patch, the draft and an import under review. The Import MVR dialog has a File | Xchange switch, None / Take / Offer per field group (default Offer), New fixtures: Automatic, and a scope of a Luma layer, an MVR layer, an MVR class or the whole patch. Review → Import ticked asks where new fixtures go (one pop-up per group, "Use for all other imported layers"), then returns to the draft. Use the strip below or the buttons inside the mockup. The command lines are sketches, not decided syntax.

One grid, three modes
  • The rows are fixtures by GUID, and the columns come from the fixture's declared properties (the 12d rule).
  • Live: a column is editable when its property is marked live (the usual Live Patch set: name, address, position, inverts, master react, …). Every other column is greyed with a lock, and a press on it says "claim Devices to change it".
  • Draft: every column is editable. The power toggle shows the claim; pressing it leaves the patch (Keep / Discard / Cancel).
  • Import: the same grid, with a Status column, cell marks and ticks. The slab's function block switches to the import's actions.
What the import marks mean
  • Orange with a tick: taken from the file (the dialog's switch was Take); the live value is under it.
  • Dashed: offered and not taken (the switch was Offer); the file's value is under it.
  • Green: a new fixture. Red row: LOST, kept unless Delete is ticked. Red cell: a clash, which is never taken and blocks Keep.
  • Blue GUID: the GUID was the match. Gold dot: Bob's own edit. Violet dot: someone's live edit that reached the draft.
Layer tree
  • The Luma layers, nested, one per fixture, drawn as a tree with folding arrows and guide lines. The selected layer filters the grid and is where New puts fixtures.
  • The selected layer (or the one under the pointer) shows a ≡ menu: New sublayer, Rename, Copy, Duplicate…, Move…, Select fixtures, Delete layer…. The bar under the tree keeps "+ Layer" and "+ Sublayer".
  • Duplicate asks for clean fixtures or cloned data (all, or chosen kinds: presets, groups, sequences, effects, layouts, masters), a first FID (the next free block, spacing kept), and leaves the copies unpatched, with new GUIDs and no MVR source. Delete layer deletes its fixtures too, after one question naming what uses them.
  • Dragging fixtures onto a layer moves them. Dragging a layer onto another makes it a sublayer.
  • In import review each layer shows its marks (new, diff, lost).
Devices › DMX › Patch
  • The claim chip and Exit belong to Devices: one draft for every device kind, and Exit saves or discards all of it.
  • The kind rail lists the kinds under Devices: DMX now (Devices.Dmx), Metadata (MVR layers and classes, shared with 3DSpatial), and a dashed slot for kinds that come later.
  • Inside DMX the strip has Patch, Fixture types and Universes, the parts of Devices.Dmx.
Import, then back to the draft
  • Under review nothing is in the draft yet. The ticks come from the dialog's Take / Offer switches, and you change them per cell.
  • The gold button reads "Import ticked (22)". First it asks where new fixtures go, one pop-up per MVR group, with the suggestion ★ first and "Use for all other imported layers". Then it writes the ticked changes into the draft and returns to it. Cancel import leaves the draft as it was.
  • Scope: both sides are filtered, but a GUID is matched across the whole patch. A fixture matched outside the scope shows as OUTSIDE with "Bring into House", and only fixtures inside the scope can be LOST.
  • After the import, the rows it changed keep a thin edge mark until Exit, so you can see what came from the file.
