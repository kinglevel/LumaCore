What an import's scope limits

The example: Bob imports Festival_R13.mvr with Scope set to MVR layer "House". Five fixtures matter. 101 is in House in both the file and the show. 905 has the same GUID in both, but the file puts it in House, while in the show it belongs to Bob's Touring package (MVR layer Touring, outside the scope). 410 is in House in the show but missing from the file. 950 is in Touring in the show and not in the file. 305 is new in the file. Each option below shows the review grid for these five.

1 · Filter both sides, match across the whole patch

The scope decides what can be NEW or LOST. A GUID still finds its fixture anywhere in the patch, so 905 is never duplicated; it shows as outside the scope and can be brought in. Only House fixtures can be LOST.

Outside the scope: not compared, never LOST
For
  • A GUID is never duplicated, which keeps the GUID rule whole.
  • A partial MVR (just the house rig) can't touch the rest: Touring is never LOST.
  • A fixture the CAD moved between layers is found and shown, not lost.
Against
  • One more row state (OUTSIDE) to learn.
  • The matching looks at the whole patch even for a small import (fast with a GUID index).

2 · Filter both sides, match inside the scope only

Only fixtures inside the scope are compared. 905 has no match in House, so it becomes NEW. Its GUID is already taken in the show, so the new copy has to get a new GUID.

For
  • Strict and easy to explain: only what's in the scope is ever looked at.
Against
  • Duplicates. One fixture in the drawing becomes two in the show, and the copy loses the CAD's GUID, so the next import can't match it.
  • That breaks the "MVR and GUID faithful" rule.

3 · The scope picks file fixtures only; no LOST unless the scope is the whole patch

The scope only decides which of the file's fixtures are read. Matching uses the whole patch, so 905 is matched and its MVR layer change is an ordinary DIFF. Nothing can be LOST unless the scope is the whole patch.
