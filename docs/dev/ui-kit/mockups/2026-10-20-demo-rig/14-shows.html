One show or two, and what git carries

Today's demo is a test fixture as much as a showcase. The rig is 1 348 fixtures with 22 manufacturer GDTFs. The two facts pull apart.

Facts

Today's demoSix AuraXB on fixtures 101–106, two universes, one sACN line, groups All / Odd / Even, user LD; built by core::demo::build from lines, written by gen-demo to library/shows/demo.luma (1 MB, committed; the test the_demo_show_builds_loads_and_is_committed fails until it is regenerated after a show change).
Who leans on it12 e2e spec files name its fixtures and groups (Fixture 101 ×22, Group 1 ×16 …); 30 Rust test files call demo::build; the screenshots script starts a station with it; the sweep and the fuzzing seed from it.
The rig's costImport + Apply + Keep: 0.5 s in release, 2.2 s in a debug build (what every cargo test pays per demo::build); the show file 8.6 MB (22 GDTFs with models), load time to measure.
Gitdemo.luma has 45 versions, 41 MB of history. At 8.6 MB a regeneration (every format bump) the rig would add that each time. The sources are small: the MVR 4.4 MB once, the groups extract 0.8 MB once.

The shows

A · Recommended

Two shows: the tests keep theirs, the rig is the showcase, built not committed

demo.luma stays what it is (the tests' six AuraXB, committed as today). The rig becomes library/shows/ti2026.luma, built by gen-demo --rig from two committed sources — library/mvr/ti2026.mvr (4.4 MB) and library/poolxml/ti2026-groups.xml (0.8 MB) — through the station's own lines (Import Mvr, Import PoolXml … Groups, SaveShow). The built file is gitignored; the station builds it on first start when missing (as the library tree is made on first write), the screenshots script and the demo test build it too. One test builds it and checks its counts (1 348 fixtures, 23 folders, 87 groups minus the skipped, 106 universes) without committing it.

  • + the test suite's cost and the repo's weight stay as they are; the showcase is as big as you like
  • + the sources are the real files; a format bump costs nothing in git
  • − two shows to know about; the startup show setting decides which one a station opens

One show: the rig replaces the demo

Every test and screenshot runs on the rig; the 12 e2e files and 30 Rust test files are rewritten to its numbers.

  • − +2.2 s per demo::build in debug across the suites; 8.6 MB per regeneration in git, or the gitignore rule of A anyway
