"Media" is the wrong word for a folder

Decided on 9: the preset types an untyped CustomId, default Media, /IdType overrides. Your objection: Media is a bad word for a generic folder. It is the exporting console's word — it has no folder id type, so you picked the least wrong one. The list is the file's, but what LumaCore calls a folder's id is ours to decide.

Facts

MVR's list (the file's numbering)0 None · 1 Fixture · 2 Channel · 3 Houselights · 4 NonDim · 5 Media · 6 Fog · 7 Effect · 8 Pyro · 9 Marker — CustomIdType is that number; a value outside the list is out of spec and the desk would drop it.
What marks a folder in the fileIts type: Generic@Grouping.gdtf (1 mode, 0 channels, 0 attributes). That is the fact, independent of the id type; The console only lets you file it under Media, Fog, Pyro … because it needs some type for a numberless fixture.
This rig23 Grouping fixtures, all Media on the desk: Media 99 ALL, Media 1 … 9 the stages and utilities, Media 7001 … 7009 the type folders under Stage 1.
Elsewhere in the listHouselights, NonDim, Fog, Pyro, Marker are real kinds a rig has; Media is "a media server"; Effect is an effect device. A folder is none of them.

What a folder's id type is called in LumaCore

A · Recommended

Folder: LumaCore's own word, written to the file as Media

The id-type list gains Folder (after Marker; no MVR number of its own). Import: a fixture whose type has no channels (Grouping) and whose id is Media becomes Folder n; export writes it back as Media so the desk round-trips. The preset's default for an untyped id stays Media; the Grouping rule turns it into Folder. The line reads Fixture Folder 7003 At 50, the grid's IDType cell says Folder.

  • + the right word in every list and line; the file is unchanged
  • − one convention to know: "a channel-less fixture's Media id is a Folder"; a Grouping fixture filed under Fog on the desk stays Fog
B

Keep Media

The file's word is the word: Fixture Media 7003.

  • + no convention, nothing to explain to a desk user
  • − the wrong word in every grid and line, forever
C

No id on a folder: by name

A folder keeps its Media id only as data for the round trip; lines reach it by name, Fixture "ACME Icarus", names unique among siblings.

  • + nothing to type but the name you gave it
  • − a long line for a deep folder; two folders named alike need the path; the desk's handle (Media 7003) has no counterpart here

Answered · Generic, the id type the spec left a gap for

Your answer: Media was not a choice, it was the least wrong default the console offered; what you want is Generic as the default id type for CIDs, usable for folders among other things. The MVR spec (fetched: mvrdevelopment/spec, Fixture table) numbers its CustomID types 0 Undefined · 1 Fixture · 2 Channel · 4 Houselights · 5 NonDim · 6 Media · 7 Fog · 8 Effect · 9 Pyro · 10 Marker and skips 3 — the slot of the console's own Universal / Generic type (the desk shows IDTYPE Generic on the Univ fixture). LumaCore's list already numbers with the gap (CustomIdType::number). So:

  • The id-type list gains Generic = MVR number 3; it is the default id type (the preset's MvrIdType default, what an untyped CustomId gets, what a new CID gets).
  • No LumaCore-only word: a folder in this rig imports as Fixture Media 7003 because the file and the desk say Media; the next rig built on the desk can use Generic and arrive as Fixture Generic 7003. Set Fixture Media 7003 "IDType" Generic moves one.
  • Probed: Media 99 resolves to the folder itself, Media 1 Thru 9 visits only the numbers that exist (as our range rule), Fixture 849.1 is a sub-fixture.

Then

  • A folder on a line: Fixture Folder 1 At 50 programs the subtree; the sidebar shows nested fixtures; Move / Delete carry the children.
  • Groups from the Default pool, the show split for the tests, what is committed, the names.
