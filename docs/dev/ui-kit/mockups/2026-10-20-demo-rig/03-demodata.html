What a Generic@Grouping fixture is to the import

A · Recommended

A nested MVR group with its name

A fixture whose GDTF is Generic@Grouping (a folder; it has no number, no address, no channels) is read as an MVR group in the fixture tree: the review shows no row for it, its children's group is it, and Apply recreates it nested under its parent folder, named. lumacore-mvr keeps the scene as the file says; the review makes the call. The empty folders (Stage 3, Pyro) come along as empty groups.

B

A fixture without a number, as today

Stays a clash row; the operator numbers it with /FidOffset or leaves it. The groups it implies stay nameless.

C

Dropped silently

Not read at all; its children sit on the layer. Loses the tree the file carries.

Finding 5 · the Default pool's groups name this rig

A group is a SelectionData of Item IDType="0" ID="840" rows with grid positions. The 87 groups of the Default pool carry 11 393 items; 3 713 are fixture numbers the MVR has, and the rest are sub-fixture ids (239.1, 849.2, 769.2.1: Mini Blinder cells, Icarus LEDs, mapping pixels). Groups alone, pulled out of the 310 MB file, are 817 KB of XML (87 groups). Presets are PresetData → Phaser (IDType 2 = fixture type, ID, Attribute) → Step with values; cues are Cue → Part → the same; macros are MacroLine Command="…" in the exporter's syntax. All of that waits for presets and sequences on LumaCore's side; the groups do not.

Finding 6 · the demo show's weight in git

Today's library/shows/demo.luma is 1 MB and has been regenerated 45 times: 41 MB of history already. This rig's show file is 8.6 MB with 22 manufacturer GDTFs (models included); regenerated on every format bump it would add 8.6 MB a time. The MVR itself is 4.4 MB and would be committed once; the groups extract 0.8 MB once.
