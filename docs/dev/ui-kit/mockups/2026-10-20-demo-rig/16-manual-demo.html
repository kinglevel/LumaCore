Two demos: the generated one and the one you save by hand

Your direction on 15: two shows — a generated demo built from the MVR and the pool XML words, to test how data comes in and to grow as more words land; and a manual demo taken from your own saves while developing, saved normally and kept in git, so a demo can be crafted by hand over time; the generated one takes its UserProfile from the manual one so it keeps up with how everything looks. One rule of the house stands in the way of the manual one, and it is this page's question.

What that does to a saved file in gitThe generated demo is immune (rebuilt from sources). A manually saved show dies at the next bump: the new binary refuses it, the old binary that could read it is gone. Every dev show of yours has died this way already; a demo meant to grow over weeks cannot.
How a bump looksA new field with #[serde(default)] — the common case — reads an older JSON fine; a renamed or restructured field does not. The refusal is a policy, not a technical limit, for the common case.

How the manual demo survives a format bump

A · Recommended

Keep it as lines, not as a file: a replayable script

The manual demo is library/demo/manual.lum, a script of command lines kept in git; gen-demo replays it on top of the generated show (Run "manual.lum" after the imports), then saves. You work on the station as usual; what you want kept, you write into the script (the journal shows every line you ran, List Journal; a /Script export of the session's lines is a small word to add). A format bump changes nothing: lines are replayed by the new binary. The UserProfile travels the same way: the profile's settings are Set UserProfile … lines, the layout a window-layout export the script imports.

  • + immune to bumps; every change reviewable as text; the house rule "every gesture is a command line" made literal
  • + the generated and the manual demo are one pipeline: imports, then your lines
  • − a saved show is a snapshot; a script is a recipe — a hand-placed layout or a drawn image is a file the script imports, not a line
B

Relax §20 for the common case: an older format loads when it still reads

An older file is loaded when its JSON deserializes with the new types (serde defaults), with a warning and an immediate re-save in the new format; refused only when it does not. Migrations stay forbidden; renames and restructures still kill a file.

  • + a saved show survives most bumps; nothing to script
  • − the decided rule falls for every show, not only the demo; the cases it does not cover are exactly the ones that hurt (a restructure), and then the demo is lost anyway
C

The saved file, re-saved on every bump by whoever bumps

The committed .luma; the one who changes the format loads it with the previous build, exports the parts, and rebuilds it with the new one.

  • − there is no previous build at hand and no export of a whole show into lines; this is a migration done by hand
