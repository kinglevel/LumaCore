The NAV inspector, round 2

Layout A from round 1, now with the features you picked from the research:

  • copy the GUID, the path or the object to your clipboard;
  • follow "Used by" links;
  • filter and search;
  • changed-value markers with their Reset line;
  • marked rows into one range;
  • a ? help overlay;
  • a log of the lines your gestures made;
  • bookmarks by GUID;
  • a pinned inspector;
  • values that flash when another station changes them.

The research covered 4 groups of tools: file managers (yazi, ranger, lf, broot, mc), dashboards (k9s, lazygit, htop), data explorers (jless, fx, visidata) and inspectors (Blender, Godot, Unity, Unreal, VS Code, DevTools). Each idea here is one that several of those tools share.

Questions

  1. Copy keys.
    A In the inspector, y copies the focused row. On a tree row, yg copies the GUID, yp the path, ya the object as a target (Fixture 101), yn the name and ys a property's Set line.recommended
    B One y that opens a small menu of the same choices
  2. The gesture log. Three lines above the command line show the lines NAV made and what you copied; L turns it on or off.
    A On by default; the profile keeps your choicerecommended
    B Off until you turn it on
  3. Bookmarks. m + letter stores the object's GUID; ' + letter jumps back to it, even after it was renumbered or moved.
    A Kept per user in the show, like Usagerecommended
    B Kept only on this device
  4. Changed values. ● marks a property that differs from its declared default, and r puts Reset Fixture 101 "PosX" on the command line (Lum already has Reset). Should there also be a toggle that shows only the changed rows? The ● marks in this mockup are examples; the registry's defaults decide.
  5. Following a link moves the NAV cursor; no command line runs and nothing changes. A link to a GUID that no longer exists shows red with "missing". recommended

Copy on every client

The keys are the same everywhere. Each client puts the text on your computer's clipboard and says "Copied".

CLIThe OSC 52 escape sequence (works over SSH; tmux needs set-clipboard on), with the native clipboard as the fallback when it runs on a desktop.
WebThe browser's clipboard (https or localhost). On a plain-http address it uses the older copy method while the key press still counts as yours; failing that, a toast holds the text, selected and ready for Ctrl+C.
AppThe page hands the text to the app over its IPC, and the app writes it to the clipboard natively.
