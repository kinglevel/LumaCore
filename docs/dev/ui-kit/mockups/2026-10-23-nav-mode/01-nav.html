NAV mode that shows what ls shows, and every object's properties

In NAV mode the tree should be the same tree ls and cd walk, with the same rows: slot number, name, kind and count. Every object should open, and the object under the cursor should show its properties without leaving the tree.

Why they differ

NAV and ls read the same children. NAV turns each object's label (DataPool 1 "Default") into its path, which the typed path (record 0106) refuses, so the object can't open or be found. ls uses the number. The fix is for NAV to use the same path and the same row text as ls, so the two can't drift apart again.

The properties are already declared once per object (the registry behind EditSetting). EditSetting Group 1 prints all of them with their values, kinds and the Set line for each. NAV should show exactly that.

How it is built

  • NAV, ls, cd and the inspector share one row builder. Paths are made from numbers and declared names, never labels, so every object opens.
  • The inspector reads the same property registry as EditSetting: identity (slot, kind, GUID, path), every property with value and kind, Used by, Tags, and the counts for a branch.
  • Keys: ↑↓ move, → open, ← close or go to parent, Tab switches to the inspector, Enter on a property gives the Set line, c makes the cursor's node the prompt's place (cd), and Esc leaves NAV. The web Terminal window gets the same thing, because it runs the same TUI.
  • NAV tests on the demo rig, so NAV can't drift from ls again.
