Import MVR · 1 · the way in and the dialog's shape

The first question of the Import MVR hardening (34g4 part 4). Decided in §34 "34g4 patch hardened" 10–11, drawn on 2026-10-17 before the Patch dialog, the MVR tree and the phone round were built: Import… → Import MVR, a File | Xchange switch, the scope and the match key, FID and universe offsets, the rig offset and rotation, None / Take / Offer per field group, LOST Mark / Delete, Ignore rotation, all saved as the user's import preset; then the review in the grid, and Import ticked. The user asked today for loading MVR files and importing them straight from a browser. So: how does the file get in, and where do the options sit on the built frame?

The question — real captures, what is fixed

Decided (10, 11)
The dialog sets scope (an MVR layer / group, a class, a tag, the whole patch; OUTSIDE for a match beyond it), the match key (Auto = GUID → FID → Name), offsets, None / Take / Offer per group (Addresses, IDs, Names, Position and rotation, Type revisions, New fixtures; default Offer), LOST Mark / Delete, Ignore rotation — the user's import preset. Review writes nothing; Import ticked writes into the draft. The 2026-10-17 artifact import-option-c.html: "choose what to take first".

Point 12: the MVR tree is the show's tree, new fixtures land in their group by UUID; the placement pop-up is left only for a group deleted in Luma. The Patch dialog's import needs the draft (the claim): Live greys the cell with the reason.
The file
An .mvr is a zip: GeneralSceneDescription.xml (layers › child lists › fixtures with UUID, GDTFSpec + GDTFMode, Addresses, FixtureID, UnitNumber, classing, matrix; AUXData: classes, positions, symdefs, mapping definitions) plus the GDTF files it names. With GDTFs it is often 20–300 MB; the GDTF route's 16 MB cap doesn't fit. The station reads it; the browser only carries it.
Where files live
library/gdtf/ today (drive::library_file: relative, sub-folders allowed); library/mvr/ is the decided store (14: Xchange fetches into library/mvr/.xchange/). Embedded GDTFs go to the fixture type store by SHA-256 like any upload.
lum.md
No word reads an MVR yet (Import Show takes parts of a show; Import FixtureType a GDTF). The import line is question 3 of this round, a lum.md discussion; this question only fixes the dialog's shape and the way in.

The options — the Import cell of the Patch dialog, the draft held · try each frame

To decide: A, B or C (the way in — the library list, Upload from this device at 512 MB with the feedback pill, a drop anywhere on the Patch dialog — is the same in all three). Recommended: A · two steps, File then Options, then the review in the grid — the dialog Insert fixtures already is (1 Choose · 2 Place): the File step is the library's library/mvr/ list with Upload and the drop zone, and what the picked file holds (scene, layers, fixtures, GDTFs embedded or missing); the Options step is the decided set with the user's preset filled in, one screen that also fits a phone; Review runs the station's match and lands in the grid (question 2). It keeps the 2026-10-17 decision, "choose what to take first", and the one way files reach the station from a browser. B fits a desk only and is the same two screens pressed into one; C makes the review the center (pick, see, adjust) — attractive, but the options then live in a strip over the grid, and a phone's grid has no room for it; the preset still has to be set somewhere.
