Drives · 2 · the names and what keeps them

Model C is taken: Root.Drives is the drive list — the local library, the volumes the station finds, the folders you add — each with the one library tree, every file dialog with the same rail. The user: "root.drives.ssda, root.drives.ssdb, root.drives.local-library, root.drives.usb1 (external drive), root.drives.smb1 etc." So the names are kind + ordinal, not the volume's label and not a bare number. This question fixes the kinds, the ordinal, and what makes usb1 still usb1 after the stick was out and in again, or after a restart — because lines keep them (LoadShow "x" /Drive usb1 in a macro), the AssetRoot map keeps them, and a person reads them.

The ground

what the OS tells us about a volume
Linux    /proc/mounts: device (/dev/sdb1), mount point (/media/rolle/KINGSTON), fs type (vfat, exfat, ext4, cifs, nfs)
         /dev/disk/by-uuid, by-label, by-id (the serial: usb-Kingston_DataTraveler_…); /sys/block/sdb/removable, rotational
macOS    /Volumes/<label>; diskutil: Volume UUID, Protocol (USB, SATA, Apple_APFS …), Removable, Internal, Network (smb://)
Windows  drive letters; GetDriveType: REMOVABLE, FIXED, REMOTE; the volume serial; the bus (USB) from the device

so every volume has  a kind (the bus or the protocol) · a stable id (UUID / serial) · a label (KINGSTON) · a mount path
Names in the tree
Under Root.Drives a step is a name (Step::Name, like Protocols.DMXProtocols.Sacn): Root.Drives.usb1.shows.rig.luma. Names are case-insensitive, no spaces, so the tree shell's ls Root.Drives.usb1.mvr and cp work as they do.
Names on a line
The drive word is the same name: Drive "usb1", Info Drive usb1, LoadShow "rig" /Drive usb1 (question 3 decides the line's form; whichever it is, the id is what is typed).
The label
A volume's label (KINGSTON, LaCie 2TB) is its display name — shown beside the id everywhere, never the id: labels have spaces, repeat (two sticks called "USB"), and change.
Station-local
The list is this station's (like NICs). A show never names a drive; an AssetRoot's station map names one. A LumaSession member's usb1 is its own stick.

The prefix is the kind the station sees; a person can rename the label, never the id. A kind the OS can't tell (a USB SSD some systems report as fixed) can be corrected once from the Drives menu (Set Drive ssdb "Kind" USB → it becomes the next free usb id, remembered).

The options — what keeps an id

To decide: A, B or C. Recommended: A · the id is bound to the volume and remembered — the first time the station sees a volume it gets the next free id of its kind (usb1) and the station writes volume id → drive id into its settings (with the label and the kind); the same stick is usb1 every time, on every day, in this station; a new stick is usb2 even while usb1 is out. Lines in macros, the AssetRoot map and a person's memory hold; the Drives menu lists absent drives greyed and lets you Forget one (its id is free again). B is the established way — the ids are slots, the first stick in is usb1 — simple, but usb1 in a macro means "whatever is in first" and an AssetRoot can point at the wrong stick; C makes the label the id and breaks on spaces, duplicates and renames.
