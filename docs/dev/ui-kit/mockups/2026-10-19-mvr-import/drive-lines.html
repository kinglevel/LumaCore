Drives · 4 · the lines (a lum.md discussion)

Decided: model C, ids bound to the volume (local-library, ssda, usb1, smb1, folder1), the drive node is the volume with the library marked and ~usb1 the short way. Now the words. lum.md is strict: a change to the syntax is a discussion first — alternatives, what it breaks, which edge case it adds — then lum.md, then code. Two things need words: how a file word names a file on a drive (LoadShow, SaveShow, Import, Export, the MVR import to come), and the Drive object itself (list, info, settings, an added folder, forgetting one). And the fence needs ~.

What lum.md says today

the grammar
option     = "/" NAME [ value ] ;         a value: NUMBER | WORD | QUOTED | …
id         = NUMBER | QUOTED ;            "An id is a number or quoted text": Interface "en1"
TREE-PATH  = ".." | "/" | ROOT-PATH | PART { "." PART } ;   no ~

file words
LoadShow "Festival 26" /NoSave /NoConfirmation
SaveShow "x" /Overwrite · /Version <stamp> · /Recovery "copy" · /Note "…"
Import FixtureType "file.gdtf"      Import Patch + Users /From "Festival"
a file name is relative to the word's library folder (sub-folders allowed, no absolute path, no `..`,
and `:` is refused: "no absolute path or drive")

the fence under Root.Drives
cp / mv / rm work on files; between Root.Drives and the show tree they are refused: that is Import / Export.
Station-local objects with keyed properties
Set Interface "en1" "HTTP" No · Set Station "Tower" "Priority" High · List Interface · Info Interface "en1"
The id of a drive
A name, so quoted where an id is quoted: Drive "usb1", like Interface "en1". As an option's value a WORD is allowed by the grammar: /Drive usb1 and /Drive "usb1" both parse; the printed form is the bare word.
The Drive object
Station-local, keyed rows like Interface: declared properties Label (text, the volume's label by default), Kind (Internal · SSD · HDD · USB · SMB · NFS · Folder; set once to correct the OS), Path (the mount; for an added folder its path), Library (Yes when LumaCore/library/ exists — Set Yes initialises it: the folders and a README; No is refused: nothing is deleted by a setting), Free, Total, State (In · Out), Since (read-only). So the Drives menu is a MenuDef grid on these, every cell a Set line — no new verb for initialising.
Added folders
Store Drive "folder1" /Path "/srv/shows" — the next free id of its kind is the name; Store Drive "smb1" /Path "//nas/shows" for a share the OS has mounted (or mounts; question 6). Delete Drive "usb1" forgets a found drive (frees its id) or removes an added one; it asks when an AssetRoot maps to it.
Ejecting
A real action with no verb today. Proposed as the one new verb of this round, Eject Drive "usb1" (the OS unmounts, the row goes Out, a sysmon line); planned until built. Not a property: nothing is set.
What it breaks
Nothing existing: every file word keeps its bare form (the local library). The fence gains ~ and ~name as a TREE-PATH start — new tokens, a grammar edit, a test.

The options — how a file word names a file on a drive

To decide: A, B or C for the file words (the Drive object, Store / Delete Drive, Set Drive "usb1" "Library" Yes, the planned Eject and the fence's ~ go with whichever). Recommended: A · a /Drive option on every file word — the file name stays what it is today, a name relative to the word's library folder, and the drive is an option that says where, with the local library as the default when it is absent: LoadShow "rig" /Drive usb1, SaveShow "rig" /Drive usb1, Import Mvr "Rig 2026 v3.mvr" /Drive usb1, Export UserProfile "Bob" /Drive smb1. It is one option declared once (F::DRIVE, like /Version), every file word takes it, the file dialogs' footers read naturally, and a macro that says /Drive usb1 means one stick (question 2). B puts the drive inside the quoted name, a syntax of its own inside text that the grammar never sees (and : is what file names refuse today); C makes file words take tree paths, which only the fence does today, and a file's dots fight the path's dots.

The lum.md change A asks for, in full

## Options — one example more
LoadShow "Festival 26" /Drive usb1                 a file word's /Drive: the drive to read or write; absent = the local library

## The tree-shell fence — the grammar
TREE-PATH  = ".." | "/" | "~" [ NAME ] | ROOT-PATH | PART { "." PART } ;   ~ = the local library, ~usb1 = that drive's library
cd ~usb1 · ls ~ · cp "Rig 2026 v4 draft.mvr" ~usb1/mvr         (a fence arg; "/" inside a quoted part stays a file name)
