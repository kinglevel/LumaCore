Drives · 6 · the service: finding, initialising, shares

The last question of the drives round. Decided: C, the ids, the volume + library, /Drive, one files element. What runs on the station to make it true: how drives are found and watched, when the library tree is created, and who mounts a network share.

Fixed by what is decided and by the rules

The watcher
A station thread (never the state thread; like discovery) reads the OS's mounts every 2 s — Linux /proc/mounts + /dev/disk/by-uuid and by-id, macOS /Volumes + diskutil, Windows the drive letters + volume serials — and sends the state thread one message when something changed; the state thread keeps the drive table in the station settings (id → volume id, kind, label, last seen), publishes it in StationView and the station feed, and writes a sysmon line: Drives: usb1 "KINGSTON" in (28 GB free, library ready) / usb1 out.
Free space
Read on the watcher's tick for drives that are in; the Drives menu and the rail show it; a save that would not fit is refused before writing (E-CMD-012 with the numbers).
The files feed
Rows for a drive + folder + kind, built on the state thread from a cache keyed by path + mtime; a folder's listing is refreshed when the watcher sees its drive change or a write of ours lands; the first listing of a big folder reads file heads on the background worker (core::background) and the rows fill in.
The local library
local-library is library/ as it is; its caches (fixturetypes/, media/.store/, logs/, stations/) are the station's, never on another drive; the backup folders (.versions, .autosave, .trash) live beside the shows on whichever drive holds them.

Two things left to decide

Recommended: initialise on the first write, never an ask — a found drive is listed as it is (Library: no); the first thing written to it (a save, an export, a copy-in, a tap on the Library cell) creates LumaCore/library/ with the folders and a README, one sysmon line; reading never creates anything, so a stick only looked at stays untouched. And shares: the OS mounts them, LumaCore finds them — a share mounted by the system appears as smb1 / nfs1 by its fs type; a share path you add with Store Drive "smb1" /Path "//nas/shows" is a Folder drive the station reads when the OS has it mounted and shows Out when not; LumaCore mounting shares itself (credentials in the keystore, platform mount calls) is a later part, planned.
