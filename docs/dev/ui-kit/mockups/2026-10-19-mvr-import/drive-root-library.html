Drives · 3 · two ways onto a drive: its root and its library

Decided so far: model C (the drive list, found volumes plus added folders, the one library tree on each), and A for the ids (kind + ordinal, bound to the volume and remembered). The user: "we need two ways onto a drive, its root and the library path, so a user can browse the whole drive and get to the library folder easily — suggestion?" A drive is a whole volume (people keep other things on a stick: the venue's PDFs, an MVR exported from Vectorworks into some folder); the library is LumaCore/library/ on it, where the station's files go and where every dialog starts. What is the drive node in the tree, and how do the dialogs and the tree shell jump between the two?

The ground

The tree
Under Root.Drives every step is a name the disk knows; the tree shell walks real folders (ls, cat, cp, mv, rm, tree with its 300 ms / 2,000-line budget). Nothing else enters it.
Lines name library files
LoadShow "rig", Import FixtureType "x.gdtf", Import Mvr "y.mvr": a file name relative to the word's library folder (sub-folders allowed, no ..); with a drive: … /Drive usb1 (question 4 fixes the form) = that drive's LumaCore/library/<folder>/. A line never needs the volume root; a file elsewhere on the stick is copied into the library first (the tree shell's cp, or the dialog's pick).
The dialogs
One file element for every load and save (question 5): the drives rail, crumbs, the list by kind. It opens on the drive's library folder of the kind (Import MVR: mvr/); the question is how it reaches the rest of the volume.
Unix
The tree shell is a fenced Unix sub-grammar (§33 18). Unix says ~ for "my home": a short way to the place you work in, while / stays the root.

The options

Suggestion, recommended: A · the drive node is the volume; the library is a marked folder in it; ~usb1 is the short way there — Root.Drives.usb1 lists the whole stick, with LumaCore first and marked ★ library (the tree shell: ls Root.Drives.usb1; cd ~usb1 = its library, cd ~ = the local library, Unix's home); the dialogs open on the library folder of their kind and their crumbs are the jump: tap the drive's name for the whole volume, the ★ Library crumb to come back; a file picked outside the library is copied in (asked once: "Copy rig.mvr into usb1's library?") so the line stays a library name. A drive's Info shows both paths. B puts the library at the node and the volume under a reserved child, which makes the real folder LumaCore/library appear twice in the tree; C lists every drive twice in the rail, which doubles the list for the rare case.
