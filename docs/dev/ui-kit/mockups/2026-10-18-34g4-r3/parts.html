Fixture parts · a proposal

Mockup for the 34g4 round 3 hardening (decisions §34, 2026-10-18): how a fixture's parts — a centre and a ring, a pixel strip, the heads of a bar — are programmed and mapped without subfixtures. The fixture stays the one object (one FID, one patch row, one selection, one grid spot; §28). A part is a focus on its values, never an object of its own. Real fixtures: MAC Aura XB (Extended) and GLP JDC-1 from library/gdtf/. The words are placeholders until lum.md.

1 · A mode declares its parts

Read from the GDTF geometry tree: a geometry that carries channels of its own is a part; channels on the root (Base / Yoke / Head) are shared by the whole fixture. Each part gets a role from rules saved in the show (like attribute rules) — the Aura XB's "Auras" and another type's "Halo" are both Ring, so programming and maps line up across types. A part with repeated geometries (12 tube sections) has cells.

2 · Programming with a part focus

Select fixtures as always (101–106). The encoder bar's Part switch narrows what the encoders set: All sets the whole fixture (both parts, as today), Ring sets only the ring. The selection, the grid and groups don't change; the focus is the programmer's, like a feature-group switch. Try it: set Dimmer on All, then switch to Ring and pull it down.

3 · How values are stored

The key is fixture + attribute + optional part. No part = the whole fixture, exactly as today, so every existing show and line keeps working. A part value exists only where you set one — sparse, never one copy per part. Rendering: a part value wins over the whole-fixture value for that part; the rest of the fixture takes the whole value.

4 · The map with parts (lines, as chosen)

Rows are part + attribute, grouped by part; parts line up by role first, then by GDTF geometry name. MAC Aura XB (Extended) → MAC Quantum Profile (one part, Main): the Main rows map straight; the Ring rows have no ring to go to — Fold onto Main (the ring's values become the head's, where Main has none of its own) or Keep unused, chosen for the whole part.

5 · Effects over parts and cells

An effect line's Resolution spreads its pattern over whole fixtures, over parts, or over cells (§28 kept cells for effects; this adds Part). A chase over the JDC-1's 12 tube sections is Resolution Cell, Part Main; the face can run a colour wave at the same time (Part Panel). Static per-cell values stay out for now — the model leaves room for them.

Why not subfixtures

Subfixtures
Every part is a fixture of its own (101.1, 101.2) with its own patch row, selection, grid spot, group place and data. A type change reshapes all of them; data scatters (handoffs/effects.md: "subfixtures are bad").
Here
One object; a part is a facet of a value and a focus in the programmer. A type change maps part roles; groups, selection and the grid never notice.
Hog
Dotted numbers aggregated on selection — still separate objects.
MagicQ
Multi-element heads matched across types by function — closest to this, without roles.
