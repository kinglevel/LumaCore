Context menu · round 3

Mockup for the 34g4 round 3 hardening (decisions §34, 2026-10-18, item 18): one context menu for every list, grid and pool. Right-click, hold without moving (touch), or the selection chip's ⋯ opens it on the selection. It is drawn from the registry — the object's verbs and its declared properties — so every list gets the same menu: the common actions, a Set part with every column the row has (fixture type, mode, revision, address, name, tags …), then what only this object does. Every pick is one line. A phone gets it as a bottom sheet.

1 · The patch grid — Live and Draft

Select rows (tap, Shift adds, drag lassos), then right-click or hold. Switch the chip between Live and Draft: in Live only the live columns can be set and the rest show why (the claim); in Draft everything can. Try Set › Mode on 104–106: a bigger footprint turns the addresses that now overlap red (decided: red until resolved, no question). Set › Fixture type would open the GDTF picker, then the attribute map.

Rules this mockup shows

Opens
Right-click; hold without moving (touch; hold-then-drag still lassos); the selection chip's ⋯; the Menu key / Shift+F10. On a row outside the selection it selects that row first.
Three parts
Common (Edit…, Renumber…, Label, Copy, Move, Delete) · Set (every declared column: shared value or ‹different›, its editor by kind) · the object's own verbs. All from ObjectDef verbs + Props; a window adds nothing of its own.
Greyed says why
An item the rights, the claim or the state refuse stays in place, greyed, with the reason under it (never hidden, so the menu doesn't jump).
One line
Every pick writes one line naming the rows (Set Fixture 104 Thru 106 "Mode" "Extended"), one Oops step.
Phone
The same menu as a bottom sheet; submenus slide in with a back row.
