# Handoff — UI keys: press / double press / hold for any button (2026-10-10)

Branch: `termiham` (now `main`). Researched and decided with the user; first version built (see Status).

> **Audit 2026-10-11 (step 11a):** branch is now `main`; code paths moved in step 8 (`apps/lumacore-station/src/{core,terminal,net,lumasession,server}/`, clients in `apps/`). What's still open from this handoff is listed in [docs/meta/roadmap.md](../../meta/roadmap.md) → Next.


Started from "double-click the ⚙ Menu button = quick backup" and widened to: any button in
the interface — core, plugin or user — can have Press / DoublePress / Hold actions, the same way.

## Decisions

| Topic | Decision |
|---|---|
| Model | Data: a key = stable id, label, icon, tooltip, owner, **Press / DoublePress / Hold commands**, optional live state. The UI engine only reports `press` / `double` / `hold` for a key id; the **server resolves and runs the command** |
| Three layers | **Definition** (registry `Root.Resources.UIKeys`, not saved) · **user keys** (on the UserProfile, saved with the show) · **placement** (layout / bars, by the UI engine) |
| Core keys | Built in, **fully locked** (Press, DoublePress, Hold): Menu DoublePress = Quick Save can't be changed or broken |
| Plugin keys | Defined in the **plugin manifest**; plugins are show data, so their keys are **global** (every user sees them) and **users can't change them** — edit the plugin instead. Namespace `plugin.<plugin-id>.<button-id>` |
| User keys | On the **UserProfile** (no per-user private keys): everyone on that profile sees, uses **and edits** them. Namespace `user.<id>`. Created / changed / deleted on the command line (published `UIKey` ObjectDef) |
| First click | **Press runs at once**; a second click within the window runs DoublePress (a key can declare that its double replaces the press, e.g. Menu closes again before Quick Save) |
| Timing | Double-press window **300 ms**, hold **500 ms**, **per user profile** (`Set DoubleClickTime 400`, `Set HoldTime 600`); the same values for every UI engine |
| Plugin capabilities | Buttons with **icons** (+ label, tooltip, commands) and **live state** (on / off / blink / badge from a tree value or command, like key LEDs). No placement hints, no overriding core keys |
| Failures | A failing action shows a notice and a red System Monitor line; never fatal; the button stays usable |
| Recovery | **CleanStart**: loads an **empty show** (unsaved changes → Save / Don't Save first; the show file on disk is untouched), **startup show → None**, **station settings to defaults** (keeps station id + token secret), **app UI prefs** for that server cleared when started from the home screen |
| CleanStart rights | `CleanStart` command: Admin. **Home screen option**: anyone, **local server only** (the way back when nothing else works) |

## Plugin manifest (TOML)

`plugin.toml` — one manifest per plugin, any number of scripts and buttons:

```toml
[plugin]
id = "strobe-tools"            # stable; namespaces its keys
name = "Strobe Tools"
version = "1.0.0"
description = "Strobe helpers"

[[script]]
file = "main.lua"
[[script]]
file = "lib/util.lua"

[[button]]
id = "strobe"                  # → plugin.strobe-tools.strobe
label = "Strobe"
icon = "icons/strobe.svg"      # file in the plugin, or a glyph
tooltip = "Flash all strobes"
press = 'Macro "Strobe On"'
double_press = 'Macro "Strobe Burst"'
hold = 'Macro "Strobe Hold"'
state = "Root.ShowData.Playback.Executors.12.on"   # live state (optional)

[[button]]
id = "burst"
label = "Burst"
icon = "⚡"
press = 'Macro "Strobe Burst"'
```

Validation reports file and line (toml crate). Actions are commands — a plugin exposes behaviour
as published commands, never UI code.

## First version (agreed scope)

1. **Registry**: `Root.Resources.UIKeys` — `UiKey {id, label, icon, tooltip, owner (core | plugin |
   user), press, double_press, hold, state, locked}`; core keys built in; `List UIKey`,
   `Info UIKey "Menu"` (published ObjectDef, read-only for core).
2. **UI engine**: elements carry `data-key="<id>"`; one gesture handler (press at once, double
   within the profile's window, hold) sends `{type: 'key_action', key, gesture}`; the server
   resolves the key and runs the command for that client (System Monitor `Cmd` line as usual).
3. **Menu double → Quick Save**: core key `menu` — Press `Menu` (opens the menu), DoublePress
   Quick Save (`SaveShow`, a "Saved" notice; an untitled show asks for a name), the menu closes
   again.
4. **CleanStart**: command (Admin, a confirmation incl. unsaved changes) and home screen option
   (local server only).
5. **Ground work in the tree** for later: `UserProfile.ui_keys` (user keys) and
   `UserProfile.settings.double_click_ms / hold_ms`, `ShowData.Plugins` (manifest + keys) as empty
   collections with their types, published in the tree.

## Status (first version built; unit + e2e tests pass)

- `lumacore-tree/src/ui_keys.rs`: `UiKey`, `UiKeyOwner`, `Gesture`, `builtin_ui_keys()` (menu:
  Press `Menu`, DoublePress `SaveShow`, replaces the press; power: Press `Menu Shutdown`),
  `resolve()` (core wins over plugin and profile keys). `ResourceRoot.ui_keys`,
  `UserProfile.ui_keys`, `UserPreferences.double_click_ms / hold_ms` (300 / 500),
  `PluginItem {plugin_id, version, description, scripts, buttons}` (manifest ground work).
- Server: `key_action` WS message → `ShellClientPacket::KeyAction` → `TuiApp::run_key_action`
  (runs the command as a UI command — echoed, `Cmd` sysmon line; double / hold result → `Notice`;
  no DoublePress = a second Press). UI events `OpenMenu`, `CloseMenu`, `Notice`.
  `GET /api/ui-keys`. Commands: `Menu ["menu"|"backup"|"shutdown"]`, `CleanStart [/Save|/NoSave]
  [/NC]` (Admin), `Set DoubleClickTime / HoldTime <ms>`; object `UIKey` (List, Info, tree
  `Root.Resources.UIKeys`). `--clean-start` server flag (dropped again on Restart).
- Web UI: `data-key` buttons (⚙ `menu`, ⏻ `power`), one capture-phase gesture handler (press at
  once; a second click at the same spot within the window = double, even on the overlay the
  press opened; hold timer for keys with a Hold); offline fallback opens the menus locally.
- App: home screen "Clean start…" (local server only): asks with the show state, then CleanStart
  over the command port or starts the server with `--clean-start`, clears this machine's UI prefs
  for it, logs in as Admin.
- Tests: tree unit tests; e2e `ui-keys.spec.ts` (9), home `Clean start` (1).

### Deviations / notes
- An untitled show is quick-saved under a generated name (`NewShow_<date>UTC`, existing
  SaveShow behaviour) instead of asking for a name.
- A backup copy on every save (up to 10 per show) — not done yet.
- Setting names after `Set` are still not offered by the completer (existing gap, also for
  clearbuffer / descriptions).
- The `--clean-start` removal on Restart is not covered by a test.
